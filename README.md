# Credit-Banking Attacks in Strategic Linear Contextual Bandits

The project studies whether a strategic arm can first under-report its context
to accumulate statistical "credit" and later over-report to gain additional
selections. It compares Per-arm LinUCB, one-sided OptGTM, bidirectional OptGTM,
and windowed bidirectional OptGTM in controlled and IID synthetic environments.

## Quick reproducibility check

Before running the full experiment, execute the smoke-sized protocol in a
separate output directory:

```powershell
python .\scripts\run_credit_banking.py `
  --quick `
  --stage all `
 --output-dir .\results\credit_banking_smoke
```

The quick mode reduces the horizon to 300, uses three calibration seeds and
three evaluation seeds, uses a smaller radius grid, and banks for 10 attacker
pulls. It checks that calibration, evaluation, aggregation, plotting, and trace
generation all run successfully; it does not reproduce the numerical results
in the report.

## Reproduce the full reported experiment

Run the following command from the repository root:

```powershell
python .\scripts\run_credit_banking.py `
  --stage all `
  --output-dir .\results\credit_banking_reproduction
```

The default full protocol performs:

- truthful-only confidence-radius calibration using seeds 1000-1049;
- primary evaluation using seeds 0-49;
- three scenarios: controlled strong, controlled weak, and IID robustness;
- seven reporting conditions;
- four learning mechanisms;
- horizon `T = 5000`, six arms, dimension five, and reward noise `sigma = 0.1`;
- 1,200 calibration episodes and 4,200 primary episodes, for 5,400 episodes in
  total;
- aggregation of paired metrics, generation of figures, and representative
  trigger traces.

The expected calibrated radius scales are:

| Mechanism | Radius scale |
|---|---:|
| One-sided OptGTM | 0.125 |
| Bidirectional OptGTM | 0.25 |
| Windowed bidirectional OptGTM (`W = 200`) | 0.25 |

The original completed outputs are stored in
`results/credit_banking_experiment/`. Using a new output directory, as shown
above, preserves those reference outputs and provides an independent
reproduction.

## Run the two stages separately

Calibration can be run independently:

```powershell
python .\scripts\run_credit_banking.py `
  --stage calibration `
  --output-dir .\results\credit_banking_reproduction
```

After calibration completes, run the primary evaluation with the same output
directory:

```powershell
python .\scripts\run_credit_banking.py `
  --stage primary `
  --output-dir .\results\credit_banking_reproduction
```

The primary stage checks that the saved calibration was generated by the
matching protocol before using its selected radius scales.

## Checkpointing and resuming

Raw episode results are appended to JSON Lines checkpoint files. If a run is
interrupted, repeat the same command with the same arguments and output
directory. Completed episodes with the matching protocol hash are skipped and
the run continues from the remaining episodes.

Protocol identifiers are derived from the experimental configuration and are
recorded in `experiment_manifest.json`. This prevents results from incompatible
configurations from being silently combined.

## Output files

Each experiment output directory contains:

```text
experiment_manifest.json          # Exact protocol and run identifiers
selected_radius_scales.json       # Calibrated scales and selection status
raw/                              # Checkpointed per-episode JSONL data
tables/                           # Per-run, paired, and aggregate CSV tables
figures/                          # Calibration and result plots
figures/traces/                   # Representative trigger traces
trace_summaries/                  # JSON summaries for plotted traces
```
## Important interpretation

The primary outcome is the **banking-specific gain**: attacker selections under
a credit-banking strategy minus attacker selections under a matched delayed
over-reporting control. Total gain relative to truthful reporting is secondary
because it combines the effect of banking with the later over-reporting phase.

All paired comparisons use the same seed, true contexts, and reward-noise
sequence. Pull-count comparisons are marked as censored when either member of a
pair fails to complete the required 100 banking pulls.

## Additional command-line options

```powershell
python .\scripts\run_credit_banking.py --help
```

Useful options include:

- `--horizon`: change the experiment horizon;
- `--calibration-seeds`: change the number of calibration seeds;
- `--evaluation-seeds`: change the number of primary evaluation seeds;
- `--trace-seed`: choose the representative trace seed;
- `--no-traces`: skip representative trace generation;
- `--output-dir`: select a separate result directory.

Changing these values defines a different protocol and will not reproduce the
reported numerical results.
